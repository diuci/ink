## 1. How ink painting works end-to-end

### Atlas layout — shelf packing at a falling density

`PaintSystem` (`src/world/paint.js:266`) owns **one 4096² RGBA8 render target** that every paintable face owns a
rectangle in. `_layout` (`paint.js:292`) is a retry loop: start at `maxDensity` texels/metre and, if the shelf packer
fails, multiply by `0.92` and try again, up to 30 attempts:

```js
let ppm = maxDensity;
for (let attempt = 0; attempt < 30; attempt++) { if (this._tryPack(faces, ppm, S)) break; ppm *= 0.92; }
```

`maxDensity` is quality-dependent (`src/main.js:245`): 30 ppm at a 4096 atlas, 18 ppm at 2048
(`src/config.js:587-590`). `_tryPack` (`paint.js:303`) is a classic sort-by-height shelf packer with a fixed
`pad = 8` texels on every side (`paint.js:272`) — the comment is explicit that the padding exists "so mip levels never
bleed between faces". At 30 ppm a 4096² atlas covers ≈ 136 m² of inkable surface at full density.

### GPU splat rendering — texture-space painting

Rather than painting into world space and projecting, **splats are rasterised as quads directly into the atlas in face
space**. `_pushQuad` (`paint.js:653`) converts a face-local rectangle `(u0,u1,v0,v1)` into atlas pixel coordinates and
emits a screen-space quad with `gl_Position = vec4(aPos, 0, 1)` (`PAINT_VS`, `paint.js:64`) — no camera involved.
Alongside that it writes `aLocal` = the quad corner's offset from the splat centre in face space, including
`dn = the centre's distance from the face plane`. The fragment shader (`PAINT_FS`, `paint.js:67-214`) then computes the
true footprint radius on this face as `r = sqrt(R² − dn²)` (`paint.js:101-103`), which is exactly what makes ink wrap
correctly across floors, walls and corners from a single spherical splash.

All quads are batched into one dynamic `BufferGeometry` with a hard cap of `MAX_QUADS = 6000` (`paint.js:31`); geometry
is drawn once per frame in `_drawQuads` (`paint.js:844`) with `setDrawRange` + `addUpdateRange` so only the used prefix
uploads.

The splat shape is a full SDF composition in the fragment shader: an organic wobbled body (`wob`, an 7-term sine
series with two `pow(max(cos,…), 28/36)` fingers — `paint.js:74-78`), up to 10 tapered rays (`sdRay` + `smin`,
`paint.js:139-152`), up to 12 satellite droplets, up to 14 fine spatter dots, and up to 6 wall drips with meandering
streams and bulbous heads (`paint.js:187-209`). Each of these is staggered in time via `vGrow.x` (`tn`), so the rays
shoot ahead of the body, droplets land a beat later (the farthest last, `land = smoothstep(tl, tl+0.2, tn)`), spatter
last, and drips run for 1.1–3.3 s (`paint.js:532`).

### Blend state — the clever part

The splat and flood materials use **split RGB/alpha blend equations** (`paint.js:380-382`):

```js
blendEquation: THREE.AddEquation,      blendEquationAlpha: THREE.MaxEquation,
blendSrc: THREE.SrcAlphaFactor, blendDst: THREE.OneMinusSrcAlphaFactor,   // RGB: "over"
blendSrcAlpha: THREE.OneFactor, blendDstAlpha: THREE.OneFactor,           // A: max
```

RGB is source-over (newest splat wins at a team border), while alpha is `MAX` — a **union of coverage**. This makes
redrawing a still-spreading splat every frame *idempotent*, which is what allows the growth animation to simply
re-emit the same quad at a larger `grow` factor each frame without accumulating.

Drying is a second fullscreen mesh over the used atlas region (`dryMesh`, `paint.js:391-407`) using
`ReverseSubtractEquation` with both factors `ONE`, subtracting `k/255` from G (wetness) every 1/40 s in steps of ≥2 —
≈6.4 s from landing to dry (`paint.js:693-701`). It is drawn in the same render pass as the splats so the mip chain
rebuilds only once per frame.

### CPU grid sync — the same edge, evaluated twice

`_initGrid` (`paint.js:322`) builds a parallel `Uint8Array` at **0.25 m cells** per face (0 none, 1 team0, 2 team1),
plus a `dead` array marking cells buried inside other geometry (`lvl.pointInside(p, 0, f.block)`, `paint.js:342`), and
turf totals for scoring. Ground-up resolution is thus `nu = round(su / 0.25)` — roughly 4 cells per metre.

`_cpuSplat` (`paint.js:610`) walks only the cells within `r * WOB_MAX` of the centre and applies **the same edge
function the GPU uses**:

```js
if (d > r * WOB_MAX) continue;
if (d / (r * blobWobble(Math.atan2(py, px), seed)) > 0.97) continue;
```

`blobWobble` (JS, `paint.js:43`) and `wob` (GLSL, `paint.js:74`) are hand-duplicated implementations of the same
formula — the comment at `paint.js:41-42` states the intent: "the GPU splat shader evaluates the identical function
(wob), so the gameplay grid and the rendered ink agree on the edge." Roller strokes use a band SDF evaluated in both
places too (`BAND_L/BAND_W/BAND_R`, `paint.js:50` vs `paint.js:624-625`).

The class docstring (`paint.js:6-8`) names the deliberate asymmetry: everything *beyond* the body edge (rays,
satellites, fine spatter, drips, cosmetic specks) is finer than the gameplay grid and **never claims turf**.

### Gameplay reads

Reading a grid cell is O(1) — `sample(faceId, u, v)` (`paint.js:869`) floors to a cell index:

```js
const i = Math.min(f.nu - 1, Math.max(0, Math.floor(u / f.cu)));
const j = Math.min(f.nv - 1, Math.max(0, Math.floor(v / f.cv)));
return this.grid[f.grid + j * f.nu + i];
```

The `(face, u, v)` triple comes free from the physics raycast: `Hit` carries `face`, `u`, `v` (`src/game/physics.js:18`,
`physics.js:64-66`, `physics.js:190`). So "is this mine to swim in" is a single array index after a ground probe:

```js
// src/game/actor.js:397-403
_surface() {
  const g = this.ground;
  if (this.grounded && g.hit && g.face >= 0) {
    const t = G.paint.sample(g.face, g.u, g.v);
    this.groundTeam = t === 0 ? 0 : (t - 1 === this.team ? 1 : 2);
  } else this.groundTeam = 0;
}
```

The same call gates wall-climbing (`actor.js:686`, `actor.js:709`), sub-ink interactions (`subs.js:477`) and bot
traversal (`bots.js:751`). Score comes from `coverage()` = `counts[i] / turfTotal` (`paint.js:887`), maintained
incrementally inside `_cpuSplat` (`paint.js:643-646`) and `_floodStep` (`paint.js:819-825`).

Coarser spatial queries use `regionStats` (`paint.js:892`), which walks blocks from the XZ spatial hash, filters faces
to `|f.origin.y − y| ≤ 2.5`, and **subsamples cells with `i += 2`** (`paint.js:908`) for speed. This is the hot
path for bots — 16 call sites in `src/game/bots.js` alone, plus one each in `specials.js:1320`, `kits/blade.js:417`,
`kits/mitts.js:728`, `kits/boomerang.js:588`.

`version` (`paint.js:277`) bumps on any grid change so the minimap can poll rather than subscribe.

### Floods (Zone Control)

`flood()` (`paint.js:717`) is a separate path: it inks an entire region as a **front running out from a centre**.
`_floodPrepFor` (`paint.js:734`) sorts a region's cells by distance and builds, once, one quad per face carrying world
position; `FLOOD_FS` (`paint.js:225`) re-tests every texel against the region's own outlines (an even-odd point-in-polygon
over up to 6 parts × 64 vertices) and the `[y0,y1]` height band, and discards anything outside this frame's ring
`r0 < r ≤ r1`. Crucially the **CPU grid and coverage counts advance in the same `_floodStep`** (`paint.js:808-842`),
stepping the sorted cell list while the GPU draws the band the front crossed — so what you see and what you swim in
agree. A wipe (`team === -1`) uses `THREE.NoBlending` to write bare floor straight into the atlas (`paint.js:260`).

### Precision tradeoffs

- **Paint is texture-space, so texel density is per-face-metre, not per-screen-pixel.** At 30 ppm one texel is 3.3 cm;
  the coverage edge is a `smoothstep` over ±1.5 `fwidth` (`paint.js:210-211`), so the rendered edge is
  anti-aliased regardless of density.
- **Gameplay precision is 25 cm**, ~7.5× coarser than the rendered body edge at high quality. A cell flips when its
  *centre* falls inside the blobby body — the `> 0.97` test rather than `> 1.0` at `paint.js:636` biases the grid very
  slightly inward so ink must visibly cover a cell before it counts.
- **Quality scales the atlas, not the grid**: `cell = 0.25` is a constructor default (`paint.js:267`) and is never
  changed by quality. So lowering quality coarsens the *picture* but leaves gameplay identical — a deliberate
  fairness decision.
- The atlas is rebuilt from scratch on stage swap (`clear()` → `rt.clear`, `paint.js:430-449`).

## 2. The ink shading model

`src/world/inkShading.js` is not a standalone material — it is a set of GLSL chunks that
`src/world/levelMaterial.js` splices into a `MeshPhysicalMaterial` at `${INK_*}` markers
(`levelMaterial.js:6`, `levelMaterial.js:38-63`). The atlas is **premultiplied by coverage**, so every channel is read
back as `pnt.<ch> / max(pnt.a, 0.02)` (`inkShading.js:120-128`).

### Reconstruction

Two-tier: `paintAt` (`inkShading.js:57`) uses `textureGrad` with gradients clamped to ≤8 texels — "trilinear +
anisotropic filtering … while never reaching mip levels coarse enough to bleed across the 8-texel face padding"
(`inkShading.js:54-56`). Close up (`texFoot < 2.4`), `paintCubic` (`inkShading.js:66-82`) reconstructs a **cubic
B-spline** with analytic gradients of all four channels in 12 taps, giving C2 round outlines and a smooth height field
at any magnification. The two are mixed by `near` (`inkShading.js:105-113`).

### Layering of height / wetness / gloss

Coverage `A` is turned into a thickness profile (`inkShading.js:140-146`):

```glsl
float s = clamp((amt - 0.5) * 1.7, 0.0, 1.0);
float hs = 1.0 - (1.0 - s) * (1.0 - s);            // 0 at the edge → 1 on the flat top
float thick = (wallF ? 0.6 : 1.0) * (1.0 + 0.5 * fresh);
gInkD = gradA * 2.0 * (1.0 - s) * 1.7 * 1.9 * gInk * thick;
```

Floors pool (a tall rounded lip, taller while fresh); walls hold a thinner clinging film that lets
`gInkKeep = 0.32 * (1 − 0.5·fresh)` of the underlying relief show through (`inkShading.js:144`).

**Wetness (G) drives gloss.** `fresh = smoothstep(0.3, 0.97, wet)` (`inkShading.js:126`) is "visibly wet for ≈ 4 s
after landing". It feeds: pigment roughness (`INK_ROUGH`: `mix(0.26, 0.14, gFresh)` over the base roughness,
`inkShading.js:190`), the coat roughness (`cr = mix(mix(0.06, 0.028, gFresh), 0.022, gWake)`, `inkShading.js:267`), the
gel micro-surface amplitude (fresh ink is *smoother* and sways gently, `inkShading.js:199-201`), and colour
(`inkCol *= 1.0 + 0.07 * fresh * fresh`, `inkShading.js:172`).

**The seam between teams** is where the model is most interesting (`inkShading.js:147-163`). The gradient of the team
share across the seam gives a signed distance `x` in texels; the gradient of *wetness* along the seam normal gives
`newer ∈ [−1,1]`. The result:

```glsl
float dh = newer * 2.4 * e1 / 2.3 + 0.9 * 2.0 * x / 0.8 * e2 * (1.0 - 0.6 * abs(newer));
gInkD += sn * dh * seam * gInk * thick;
```

So the newer (wetter) ink physically rides **over** the older one on a rounded lip, while two inks of similar age meet
in a symmetric crease. A `seamShadow` term darkens the lower side and adds a thin dark line (`inkShading.js:162`).

**Ripples** (`INK_SLOPE`, `inkShading.js:221-253`) are a 24-entry uniform table fed straight from `paint.rip` /
`paint.ripP` each draw by `inkBeforeRender` (`inkShading.js:34-45`). Each is a Gaussian wave packet whose analytic
gradient is projected into the face tangent frame and added to `slope`; crests also raise `gWake`, which sharpens the
coat.

### Blending ink over surface

Colour is `team × (0.93 + 0.13·tone)`, with the thin lip lightened/oversaturated, the thick body deepened, seam shadow
multiplied in, and the whole thing mixed over the base at `gInk` (`inkShading.js:164-185`). A `halo` term outside the
covered area does different work per orientation: floors get a **contact shadow thrown away from the sun** (using the
coverage gradient direction vs. the sun direction in face space, `inkShading.js:176-180`), walls get a **damp tinted
soak halo** (`inkShading.js:182-183`).

The lighting overrides are the most opinionated part:

- `INK_LIGHTS` installs a clearcoat that *is* the ink (`material.clearcoat = gInk`), then tames Fresnel:
  `clearcoatF90 = mix(1.0, 0.3, gInk)` and `specularF90 → 0.35`, so a low gameplay camera still sees team colour
  instead of washing out to sky-white (`inkShading.js:274-278`).
- `INK_LIGHT_MAPS` desaturates the ambient `irradiance` toward its luminance weighted by `gInk`
  (`inkShading.js:284-290`) — "ink keeps its hue in shade" — and pushes `clearcoatRadiance` toward a neutral sheen,
  then re-tints it by the pigment's own normalised colour so "a blue sky never turns yellow ink olive"
  (`inkShading.js:291-299`).
- `INK_SHADE` (`inkShading.js:303-314`) computes a shade factor and swaps `indirectDiffuse` for a chroma-boosted
  "rich" variant (`c² · (L(c)/L(c²))`) — same brightness, deeper hue — explicitly "never browner".

## 3. Stage data format

### The box/ramp DSL

`src/world/mapkit.js` is 62 lines and defines the entire vocabulary (`mapkit.js:5-7`):

- `B(x0,x1, y0,y1, z0,z1, opts)` — axis-aligned box.
- `R([x,y,z]low, [x,y,z]high, width, opts)` — ramp slab; its top surface runs from the low edge-centre to the high.
- `O(cx, cz, w, d, y0, y1, deg, opts)` — box turned about Y.
- `OCT(cx, cz, R, y0, y1, o)` — octagon as 3 boxes + 4 rotated corner slabs tucked 0.1 m lower (`mapkit.js:33-45`).
- `ARC(cx, cz, r, t, y0, y1, a0, a1, n, o)` — a curved wall as `n` turned segments meeting at inner corners
  (`mapkit.js:48-55`).
- `OCTRAMP(...)` / `R_(...)` — ramp helpers.

`opts` carries `{ color, pattern, paint, solid, tag }` plus a semantic flag vocabulary read in
`src/world/level.js:44-58`: `roof` (off-limits top, slides you off), `perch` (standable but never inkable), `grate`
(squids + ink + shots pass through, never inkable), `rail` (kids blocked, shots/ink pass), `noNav`, `noPaint`, `mural`,
`hidden`, `bevel`, plus the mode tags `onlyIn` / `notIn` (see variants below).

`src/world/maps.js:1-2` states the mirror rule: everything in `half` is mirrored by a **180° rotation about Y**
(`(x,z) → (−x,−z)`), with Alpha spawning at −Z and Bravo at +Z. `mirrorDef` (`level.js:408-415`) also flips murals and
`noPaint` normals.

Every stage except Halyard lives in `src/world/stages/<id>/` with four files: `layout.js`, `props.js`, `surfaces.js`,
`murals.js` — statically imported and spread into `STAGES` by `src/world/stages/index.js:34-42`.

### Mode variants

`src/world/variants.js` (21 lines) is a clean small system: a layout piece or dressing item may carry
`onlyIn: 'zones'` / `notIn: 'zones'`. `hasVariant` decides whether a Zone Control build differs at all; `variantKey`
yields `'<id>'` or `'<id>.zones'`, which is simultaneously the **world key and the lightmap filename**. If nothing is
tagged, the turf bake is reused — which is exactly what the shipped assets show: `tidewater.json` and
`tidewater.zones.json` carry the **identical hash** `8b3b5d82`, while crossmarket has only one bake (no tags).

### Geometry, hidden faces, and the bevel

`Level._build` (`level.js:25`) concatenates `single` + `half` + mirrored `half` + collision-only props.
`_addBlock` (`level.js:37`) builds oriented axes, an AABB, and computes ramp slabs as thick tilted boxes whose
underside reaches the floor (or keeps `d.thickness` when `thin: true`, i.e. a free-spanning plank, `level.js:82-83`).
A 4 m spatial hash over XZ (`level.js:108-138`) backs `queryBlocks`, used by paint, physics and nav.

`_buildFaces` (`level.js:159`) emits only *visible* faces: `_faceHidden` (`level.js:209`) samples a grid of points
0.03 m outside the face at ~1.25 m spacing and discards the face if every one is inside another solid block. Walls get
`groundedBottom` (whether the wall's foot meets a floor, `level.js:198-201`), which later drives the drip behaviour.
Face classification: `wall = |n.y| < 0.3`, `turf = n.y > 0.7`, `ceiling = n.y < −0.5`, `paintable = b.paint && n.y > −0.5`
(`level.js:187-188`).

`buildGeometry` (`level.js:248`, the largest function in the file at ~135 lines) emits **rounded boxes**: exposed edges
get quarter-round strips and octant corner patches, with an exposure test that walks the shared edge
(`bevelled()`, `level.js:288-303`). Bevel vertices map into their face's paint atlas rect, so ink wraps smoothly over
the rounded edge. The 8-texel padding absorbs the extrapolation. Vertex attributes are `position, normal, color,
paintUv, lightUv, faceUv, faceData(4), faceFlags(3), faceTan(3)` — a fairly wide interleaved-attribute set, chosen so
the gigantic level shader has everything it needs without branching on face identity.

### AO baking pipeline

`build/bake-ao.cjs` runs **inside the real game** (`require('./../electron/main.cjs')`, `bake-ao.cjs:17`) specifically
so prop colliders are present and the layout hash matches what ships (`bake-ao.cjs:3-4`). It calls
`window.__inkwave.api.startMatch(...)`, waits for the intro, `debug.freeze()`, then injects `PAGE_BAKE`
(`bake-ao.cjs:37-80`):

- `L.layoutLightmap(8, 2048)` — deterministic shelf layout independent of the paint atlas/quality
  (`level.js:224-241`), which also computes `layoutHash` as an FNV-1a checksum over every face's origin and extents.
- 96 cosine-weighted Hammersley rays per texel (`bake-ao.cjs:43-44`), ray-cast against the game's own `Physics.raycast`
  with distance-weighted occlusion `1 − hit.dist/dist`.
- Per-texel rotation of the ray set keyed on `(faceId, i, j)` to break banding, then a 3×3 blur inside the face's own
  rect (`bake-ao.cjs:58-72`).
- Tone curve `max(0.65, 1 − 0.9·occ^1.1)` (`bake-ao.cjs:13`, `bake-ao.cjs:65`) — floor 0.65 so fully enclosed spots
  never go black.
- A hand-rolled 8-bit grayscale PNG writer (`grayPNG`, `bake-ao.cjs:20-34`) instead of a dependency.

The result is `{id}.png` + `{id}.json` `{hash, size, ppm, rays, dist}`, plus a matching `.zones` pair for variants.
On load, `_loadLightmap` (`src/main.js:268-283`) recomputes the hash and **refuses a stale bake**, nulling all
`face.light` and warning "re-run tools/bake-ao.mjs" (`main.js:272`). The texture is fetched with `?h=<hash>` for cache
busting (`main.js:273`).

Note the **runtime vs. bake density mismatch**: `layoutLightmap` defaults to 5 ppm (`level.js:224`) but the bake uses 8
ppm (`bake-ao.cjs:13`), and the runtime call passes `meta.ppm` from the JSON so the two agree. Lights are also lit at
runtime by `setLevelLamps` (`levelMaterial.js:28`), which injects up to 12 real punctual lamps into the BRDF with a
per-pixel world-space cull (`levelMaterial.js:12-24`) — so the bake is AO only, not full baked lighting.

Zone JSON files (`src/world/zones-data.js`) are separate hand-authored polygon data: `rect`, `orect` (turned rect),
`circle` helpers, with `y0/y1` floor bands, keyed per stage, using rotated local axes like `K35 = [0.819, −0.574]`
(`zones-data.js:10-12`). Layouts without their own `zones` get them injected in `maps.js:119`.

## 4. Procedural content generation

Nothing in the world layer is loaded as an image or model. The only shipped binaries are fonts, the AO PNGs, stage
thumbnails and (outside this scope) songs.

### texlib — GPU-generated PBR layers

`src/world/texlib.js` generates a `DataArrayTexture` library at boot. One **uber fragment shader per material group**
(all original layers in one program, marina set in another, stairs in a third, and one per stage — see below), with
each layer behind a `uMat` uniform switch, renders into a `WebGLArrayRenderTarget` with **three MRT colour
attachments**: albedo (sRGB8_A8), normal (RGBA8), orm (RGBA8 = cavity/roughness/metalness/height)
(`texlib.js:29-33`, `GEN_MAIN` at `texlib.js:171-201`).

Two decisions stand out:

1. **2×2 sub-sampling per texel.** `GEN_MAIN` evaluates the surface at four sub-sample positions offset by
   `(k&1, k>>1) − 0.5) * 0.5`, box-filters albedo/ORM, and derives the tangent-space normal from the sub-sample
   **height gradient** (`texlib.js:194-198`). Because heights are in metres, bevels and grout joints have physically
   correct slopes rather than an artistic normal-map strength.
2. **Driver-compile-time discipline.** The comment at `texlib.js:34-36` is explicit: materials declare their noise up
   front (`prep` → up to 4 fbm + 2 Worley requests), one shared loop evaluates them, loops stay rolled via the `uOne`
   uniform (=1, so trip counts are non-constant), and there is no integer modulo — `wrp` is a float `floor`-based wrap
   precisely because "integer % by a non-constant divisor is emulated in software and bloats driver compile time"
   (`texlib.js:120-121`). Compilation is async via `KHR_parallel_shader_compile`.

Patterns are periodic and band-limited: `gn` is gradient noise on a wrapped integer lattice (`texlib.js:126-134`),
`worR` is tileable Worley with jitter (`texlib.js:141-152`), all hashing is integer PCG (`texlib.js:116-119`).
Anti-aliasing uses `aa(edge, x) = smoothstep(edge ± PX*0.75, x)` where `PX = uScale / (2·uRes.x)` is half a texel in
metres (`texlib.js:158`, `texlib.js:175`).

Anti-tiling modes: `TEXLIB_PLAIN` (0), `TEXLIB_GRID` (1 — per-repeat random dihedral transform masked by `sym`;
justified because every grid layer has joints on its repeat borders so the hard switch is invisible),
`TEXLIB_HEX` (2 — 3-tap hex-tile stochastic blend, Mikkelsen 2022, `texlib.js:40-46`).

Helpers exported for consumers: `texlibSample`, `texlibTangentFrame`, `texlibPerturbNormal`, `texlibDetail`,
`texlibSpecularAA` (Toksvig roughness widening), `texlibMacro`, `texlibCoverage` (`texlib.js:39-80`).

The 19 built-in layers plus 'detail' and 'gel' (`texlib.js:9-10`). Each is genuinely a written description of a
material, e.g. `concrete` is "2 × 2 m cast panels: hairline seams, per-pour tone, one form-tie hole per panel, sparse
bug-hole pores" (`texlib.js:217`).

**Stage surfaces** extend this with a reserved slot range. `PATTERN` 0–27 is the shared kit; each stage owns three
slots from 28 up (`stages/surfaces.js:14`), and `levelMaterial.js:77-89` builds the slot→layer map by searching
`STAGE_SURFACES`, falling back to concrete. Each stage's layers get their own uber-program (`group: 3 + k`,
`surfaces.js:23`) in parallel, keeping each program small. Stage materials are full GLSL bodies using the shared
`GEN_COMMON` helpers — `saltpan/surfaces.js:29-65` implements a crystallising salt pan with domed crust plates,
crystal ridges, pink brine pools, slush margins and floating hopper crystals; `terraces/surfaces.js:59-92` implements
0.3 m octagonal terracotta tiles with glazed majolica *tozzetti* and mixed cobalt/white/lemon corner inserts.

### props.js — a code-built prop kit

`src/world/props.js` (3240 lines) is a procedural prop library. Its structure:

- **Primitives** (`props.js:81-298`): `chamferBox`, `roundBox`, `latheGeo`, `tubeGeo`, `extrudeGeo`, `blobGeo` (seeded
  lumpy sphere), `puffGeo`, `arcPts`, `canopyGeo`, `parasolGeo`.
- **A shared texture atlas** (`AW = AH = 2048`, `props.js:323`) drawn with Canvas2D at boot. `REG` is a region
  registry with `regUV` (`props.js:348`), and `drawAtlas` (`props.js:392`) + `drawStreetPrint` (`props.js:625`) paint
  several hundred procedurally drawn signs, posters, stickers, packaging and street prints — including helpers like
  `splatShape`, `halftone`, `starburst`, `tornEdges` (`props.js:554-606`).
- **Template caching**: `TPL` map + `tpl(key, fn)` (`props.js:300-302`) memoises geometry across placements.
- **A Builder** (`props.js:1140`) that merges parts into per-material buckets via `mergeParts` (`props.js:1087`), with
  `CASTS` (`props.js:3064`) deciding which buckets cast shadows. Fewer merged meshes = fewer draw calls.
- **~62 prop types** `D.railing` … `D.pot` (`props.js:1209-2992`), each with a `desc`, `params` and `variants`, plus
  `PROP_TYPES` for the lab tools (`props.js:3326`).
- Cloth: flags and banners use a custom vertex shader with per-vertex `flex` and `wave` attributes plus a matching
  depth material so shadows deform too (`props.js:1018-1086`).

Two large satellite packs exist: `props-marina-dock.js` (1855 lines) and `props-marina-vessels.js` (2244 lines,
including `hullGeo` with sheer/stripe/bottom/deck parameters). **Interesting pattern**: `props.js` imports nothing
from the stage kits — the packs receive `H` (THREE + kit helpers) at `register(D, H)` time, an inversion that keeps
`props.js` free of stage dependencies and lets each stage destructure only the helpers it needs
(e.g. `saltpan/props.js:14`). Notably `cargo/props.js:16` and `kelpline/props.js:16` use **identical destructuring**,
confirming the copy relationship described in §9.

### environment.js — code-built world shell

`src/world/environment.js` (3003 lines) builds sky, sea and horizon entirely in shaders:

- Three themes (`THEMES`, `environment.js:37-106`): `day`, `sunset`, `golden`, each ~18 lines of explicit art
  direction — sun azimuth/elevation, key/fill intensities, zenith/mid/horizon/ground gradient stops, cloud lit/shade

- The sky uses a **baked cloud texture** (`CLOUD_W = 2048, CLOUD_H = 640`, `CLOUD_BAKE_FRAG` at `environment.js:203-330`)

- JS-side generation includes a seeded `mulberry` (`environment.js:1131`), `fbm`, a sinusoidal wave normal texture

## 5. The render pipeline

### Chain

`src/core/renderer.js:1-3` documents it: **MSAA HDR target → optional GTAO → bloom → grade/vignette → output**.
`_buildComposer` (`renderer.js:111-153`) constructs:

1. `EffectComposer` on a `WebGLRenderTarget(w*pr, h*pr, { type: HalfFloatType, samples })` (`renderer.js:121`).
2. `RenderPass`.
3. `GTAOPass` if `q.ao` — `blendIntensity = 0.8` so "fully enclosed spots keep 20 % of their light"
   (`renderer.js:131`); tuned for **contact AO** with a metre-scale radius (`radius: 1.1, samples: 12`,
   `renderer.js:134`) plus a Poisson denoise tuned to `radius: 6, rings: 2` (`renderer.js:135`).
4. `UnrealBloomPass` with `BLOOM = [0.28, 0.45, 2.4]`, overridden per theme (`renderer.js:15`, `renderer.js:213-214`).
5. `ShaderPass(GradeShader)`.
6. An optional injected screen-FX pass (`setExtraPass`, `renderer.js:156`) that runs in HDR linear before output.
7. `OutputPass` (tone mapping + colour space).
8. `SMAAPass` **only where MSAA was skipped** (`renderer.js:149`).

### The grade shader

`GradeShader` (`renderer.js:17-62`) does, in order: exposure; **vibrance** (extra saturation for low-chroma colours
only, so team ink never clips — `renderer.js:42-45`); log-space contrast around mid grey `0.18 * pow(c/0.18, contrast)`
preserving HDR ordering (`renderer.js:47`); a cool-shadow/warm-highlight split tone that is **dialled out for
saturated colours** so team ink keeps its exact hue (`renderer.js:49-50`); aspect-correct vignette; and a hurt effect
that only drains saturation and darkens the rim (the HUD draws the coloured edge, `renderer.js:55-58`).

Theme grades are applied lazily once per theme change (`renderer.js:204-215`), reading `G.env.grade`.

### Vendor-specific workarounds — a notable engineering decision

Three hardware-targeted hacks sit in this file:

- **Apple GPU detection** (`isAppleGPU`, `renderer.js:76-80`) via `WEBGL_debug_renderer_info`. The header explains the
  cost: "multisampled half-float targets cost ~30 ms/frame at 1920×1200 on an M1 Pro" (`renderer.js:2-3`). When
  detected: `samples = 0` (SMAA instead) and GTAO runs at **half resolution** by monkey-patching `ao.setSize`
  (`renderer.js:136`).
- **Shadow filter replacement** (`patchShadowFilter`, `renderer.js:66-74`): a regex replace of the
  `shadowmap_pars_fragment` chunk, swapping r186's "5-tap rotated Vogel disk with per-pixel noise" for a noise-free
  3×3 grid of hardware-compared taps. It **verifies the regex matched first** and warns "shadow chunk layout changed;
  keeping stock PCF" otherwise — good defensive practice for a chunk-string patch.
- **`checkShaderErrors` gating** (`renderer.js:88`): shader status checks are disabled unless `?shadercheck` is in the
  URL, because they make every compile synchronous and "a mid-game compile then stalls input, netcode and all."

### Quality presets

`QUALITY` (`src/config.js:585-591`) is a flat table of five keys — `pixelRatio`, `shadowSize`, `msaa`, `bloom`, `ao`,
`paintAtlas`, `particles`:

| preset | pixelRatio | shadow | msaa | bloom | ao | paintAtlas | particles |
|---|---|---|---|---|---|---|---|
| low | 0.75 | 1024 | 0 | off | off | 2048 | 0.4 |
| medium | 1.0 | 2048 | 2 | on | off | 2048 | 0.7 |
| high | 1.5 | 4096 | 4 | on | **on** | **4096** | 1.0 |
| ultra | 2.0 | 4096 | 4 | on | on | 4096 | 1.0 |

Note `paintAtlas` only differs between low/medium and high/ultra, so it is a **two-step** quality knob, not four.
`applySettings` (`renderer.js:161-172`) rebuilds the composer and force-marks every material `needsUpdate` when
quality or shadows change — a full shader recompile.

There is also **dynamic resolution scaling**: `setDynamicScale` clamps between `dynFloor()` (never below 0.75 of CSS
pixel density, `renderer.js:175-178`) and 1.0, and is disabled at ultra (`renderer.js:180`).

### three.js vendoring

`vendor/three` (502 files, 10.67 MB) holds `build/` and `jsm/`. `index.html:20-22` maps them:

```json
{ "imports": { "three": "./vendor/three/build/three.module.js", "three/addons/": "./vendor/three/jsm/" } }
```

`package.json:47` also declares `three: ^0.186.0` as a runtime dependency, but the browser never resolves it — the

matters only for tooling (`build/bake-ao.cjs` does `await import('three')` inside the page, `bake-ao.cjs:38`, which
resolves through the same import map).

## 6. Procedural audio

The audio layer is 4062 lines across `src/audio/audio.js` (2462), `music.js` (1426) and `bossAudio.js` (174), declared
by `docs/CONTRACTS.md` as "fully procedural WebAudio". No audio file is loaded for SFX or for the synthesized score —
scoped to this analysis, `audio.js` and `music.js` build every voice from oscillators, noise buffers, filters and
envelopes. (A full voice-by-voice breakdown of synthesis primitives, buses and spatialisation is beyond the space
available here and was not verified line-by-line for this report.)

The parts verified: callers use a uniform `G.audio?.play(name, { pos, volume, pitch })` /
`G.audio?.loop(name, { pos, volume, pitch })` interface returning a handle with `set(...)` and `stop(fade)`. This is
exercised from the netcode for *remote* players' continuous weapon sounds — `src/net/netmatch.js:432-448` allocates a
loop per remote actor and drives its `pitch` from replicated charge/spin/roll state:

```js
want('charge', wr.charging && k === 'charger', 'charger_charge',
     (h) => h.set({ pos: a.pos, volume: 0.35, pitch: 1 + wr.charge * 1.5 }));
want('spin', (wr.charging || wr.streaming) && k === 'splatling', 'splatling_spin',
     (h) => h.set({ pos: a.pos, volume: 0.4, pitch: wr.streaming ? 1.5 : 0.6 + 0.85 * wr.charge }));
```

with per-actor loop ownership (`a.net.loops`) and explicit `_stopLoops` cleanup on death, removal and adoption
(`netmatch.js:449`). Event playback and derived moments also emit one-shots with distance-attenuated volume, e.g.
landings at `netmatch.js:405` scale `volume` by impact speed and gate on `a._nearCamera()` (30 m, `actor.js:391-394`).

`docs/NET.md:130-134` references announcer-style hooks and `bossAudio.js` adds the HULLBREAKER layer (174 lines).

## 7. Netcode

### Relay architecture

`server/src/index.js` (144 lines) is a Cloudflare Worker + one Durable Object per room code. The Worker validates the
code shape (`CODE = /^[A-Z0-9]{4,8}$/`), requires a WebSocket upgrade and applies an **origin allow-list**
(`ORIGIN_OK`, `server/src/index.js:22-23`) permitting only `*.inkwave-aah.pages.dev` plus localhost/private-LAN
origins.

The `Room` DO is deliberately dumb: `server/src/index.js:5-6` says "game payloads are forwarded as raw strings (never
parsed here)". Membership, host election (oldest member by `seq`) and join refusal are its whole job — unknown code,
full (`MAX = 8`), or `locked` mid-match (`index.js:70-75`). Anti-abuse is three-layered: message size cap
`MSG_MAX = 65536`, a 90 msg/s rate window with `BURST_STRIKES = 4` and a 3× hard trip, and a liveness sweep
(`index.js:105-109`).

Hibernation is handled properly: membership is rebuilt from `getWebSockets()` + `deserializeAttachment` in the
constructor (`index.js:53-55`), and `"ping"` is answered by `setWebSocketAutoResponse` **without waking the room**
(`index.js:52`), so an idle lobby costs nothing. The alarm sweep drops sockets silent for 20 s in a match / 150 s in
the lobby (`index.js:28`), specifically so "their squidkid is handed to a bot instead of standing frozen"
(`index.js:25-27`).

Wire format, client → room: `"b|<payload>"` broadcast, `"s|<toId>|<payload>"` unicast, `{"t":"lock","v":bool}` and
`"ping"`. Room → client: `"m|<fromId>|<payload>"` plus JSON control frames `welcome` / `join` / `leave` / `err`.
Routing is done on **`charCodeAt` rather than string parsing** (`index.js:110-123`) — a micro-optimisation in the
relay's hottest path.

### Transport

`src/net/transport.js` (110 lines) is the client side. `relayURL()` (`transport.js:10-16`) picks `?relay=` → a local
`wrangler dev` on `:8787` for localhost/LAN hosts → the production worker. It pings every 2 s and measures RTT from
the oldest unanswered ping (pongs arrive in order), smoothed with `rtt += (r − rtt) * 0.3` (`transport.js:53`).

There is an inline **network simulator** for debugging (`transport.js:21-25`, `transport.js:68-72`), driven by
`?netlag=&netjitter=&netspike=`; it models a *TCP-like* delay line where late packets bunch up
(`Math.max(..., SIM.last)`) and `netspike` holds everything behind a 250 ms hiccup. That is a notably realistic
testing affordance.

### Ownership model

`src/net/netmatch.js:1-3`: "Every actor has one owner: each player owns their squidkid, the host owns the bots (and
any actor whose player left)." Owners simulate at full framerate and stream a **20 Hz** tick
(`TICK = 1/20`, `netmatch.js:30`). Nobody else simulates someone else's squidkid. A leaving player is handed to the
host as a bot *from exactly where it was drawn* (`_adopt`, `netmatch.js:692-707`): position, teleport counter, and a
cleared correction offset — `a.netTp = a.net.tp || 0` "continue the teleport counter everyone else has seen: no false
snap" (`netmatch.js:702`).

### Message types

`_sendTick` (`netmatch.js:190-203`) packs one message: `{ k:'t', ts, a:[packed actors], e:[events] }`, plus the boss
snapshot and a host clock `c:[state, time]` at 2 Hz. Actor packing is a **25-element array** (`packActor`,
`netmatch.js:723-751`) with a 19-bit flag word `F` (`netmatch.js:41-45`) and everything rounded to 2–3 decimals.
Event kinds (dispatched in `_play`, `netmatch.js:464-498`): `'s'` splat, `'p'` projectile, `'b'` bomb, `'tr'`
animation trigger, `'ev'` forwarded game event, `'k'` kit world-object ghost, `'bm'`/`'bc'` boss move/crablet, `'z'`
zone decision. Control messages (`onMessage`, `netmatch.js:206-221`): `'hit'`, `'dh'` (device hit), `'bhit'` (boss
hit), `'st'` (host state), `'res'` (result), `'end'`, `'own'`.

Note `'own'` is routed to `_ownership`, which is an empty stub: `_ownership() { /* reserved: explicit transfers */ }`
(`netmatch.js:709`). A genuinely dead wire message type.

### Prediction / interpolation

This is the strongest part of the codebase. There is no client-side rollback; instead:

- **Local player = prediction by construction.** You simulate your own squidkid, so controls are instant.
- **Remote players = interpolation on a per-sender playback clock** (a "smoothed timeline"). `_advance`
  (`netmatch.js:271-284`) runs one clock `p.tr` per sender, in the sender's time:
  - `offset` is set from the **fastest packet ever seen** (`if (o < p.off) p.off = o`, `netmatch.js:236`) — the
    network floor — then creeps up at `0.0025` per packet.
  - `delay` = `quantile(gap, 0.95) + quantile(late, 0.9) + 0.012`, clamped to 70–300 ms (`netmatch.js:244`), with
    **asymmetric easing** — quick to add buffer (`* dt * 2`), slow to trim it (`* dt * 0.35`, `netmatch.js:274`).
  - The clock advances with *this client's own frame time* and steers toward `now − offset − delay` at ±8 % for small
    errors / ±20–25 % for large ones, then **slows to as low as 0.5× when fewer than 15 ms of the sender's path remain
    buffered** (`netmatch.js:281`) — it will not run off the end into a guess.
  - `p.rate` itself eases (`* dt * 6`) so pace changes are never abrupt (`netmatch.js:282`).

- **Path evaluation** is `_pathAt` (`netmatch.js:288-303`): **cubic Hermite using the owner's own velocities as
  tangents**, which the docstring notes gives C1 continuity — "no corners at tick boundaries" at 20 Hz. If the buffer
  runs dry it extrapolates **ballistically for at most 180 ms** then holds, and only applies gravity when the last
  sample was airborne (`netmatch.js:300`).

  The Hermite has a nice vertical special case (`hermite`, `netmatch.js:774-777`):
  ```js
  let y = h00*a.y + h10*d*a.vy + h01*b.y + h11*d*b.vy;
  if ((a.f & F.grounded) || (b.f & F.grounded)) y = Math.min(Math.max(a.y,b.y)+0.02, Math.max(Math.min(a.y,b.y)-0.02, y));
  ```
  i.e. "never through a floor both ends are standing on" — landing velocities jump, so the pure Hermite would dip.

- **Corrections are measured exactly and critically damped.** `_sample` (`netmatch.js:305-346`) re-evaluates the path
  at *last frame's* time and diffuses the difference `(prevRaw − pathAt(prevT))` into an `err`/`errV` pair that decays
  as `k = exp(−ω·dt)` with `ω = 13` (`netmatch.js:340-342`) — a critically damped spring, so the fix is applied as a
  position offset that settles without a pop *or* a speed kick. Errors ≥ 4 m are treated as genuine relocations and
  shown immediately (`j2 >= 16`, `netmatch.js:335`). Respawns carry a `tp` counter, and when it changes the proxy
  **snaps** (`snapNow`, `netmatch.js:316`).

- **Two more refinements worth calling out.** A respawning remote actor stays hidden until its new life's first sample
  arrives (`n.spawnPending`, `netmatch.js:420-426`), so it never flashes up where it died. And on ownership handoff
  the offset is seeded from where the actor was last drawn (`netmatch.js:322-328`), so a host migration glides rather
  than teleports.

### How remote players are drawn

`applyRemote` (`netmatch.js:349-429`) is the proxy equivalent of `Actor.update`. It sets
`a.pos = sampled path + decaying correction`, derives gait from the sampled velocity, computes `netTurnRate` from the
yaw delta, and then reconstructs **every piece of state the animation system needs** from the packed flags: form,
submerged, climbing (with wall normal), grounded, ground team, on-enemy-ink, hp/ink/special, invulnerability,
super-jump phase, and the full weapon-pose set (`charging/charge`, `rolling/streaming/burstFrac`, `aimingSub`,
`firingT`, `flick`, `slosh`, `lockT`, dualie dodge). Kit-specific pose state round-trips through
`netState`/`netApply` (`netmatch.js:398`). Finally it calls `a._finishFrame(dt)` — **the same animation entry point a
local actor uses** (`docs/NET.md:78-80`).

Derived moments are reconstructed rather than sent: landings are detected by `!prevGrounded && grounded` and fire the
squash, splash FX and a speed-scaled sound (`netmatch.js:400-408`); squid-in/out transitions fire their own sound and
FX (`netmatch.js:409-412`).

### Ink, hits, and authority

The ink replication rule is unusually elegant. Every `paint.splat()` an **owner** performs is recorded with its seed
and replayed exactly (`recSplat`, `netmatch.js:109-114`; hooked inside `PaintSystem.splat` itself at
`paint.js:468-472`), so `blobWobble` produces the identical shape on every screen and all clients show the same turf.
Ghost projectiles are muted via a counter `this.mute` that `PaintSystem` reads (`paint.js:470`) — so other players'
projectiles are visual-only and never paint or damage.

Authority is **shooter-authoritative for hits, victim-owned for application**: `sendHit` (`netmatch.js:163-167`) sends
to `victim.owner`, and `shouldApplyHit` (`netmatch.js:711-717`) returns `'drop'` for a remote attacker, `'send'` for a
remote victim, `'local'` otherwise. The host is authoritative for the clock, the judge, Zone Control rules and the boss
(`sendResult`/`_result`, `netmatch.js:650-665`).

Remote weapon loops are re-synthesised from replicated state rather than streamed (`_voices`, `netmatch.js:432-448`),
so continuous sounds cost zero bandwidth.

## 8. Electron packaging and dual web/desktop deployment

### Why a custom scheme

`electron/main.cjs:1-2` states the reason plainly: "ES modules + import maps don't load from `file://`". So the shell
registers a **privileged `app://` scheme** (`main.cjs:27-29`) with `standard, secure, supportFetchAPI, stream` and
serves the repo root through it (`main.cjs:138-153`). Path traversal is guarded by `if (!file.startsWith(ROOT)) return
403` (`main.cjs:141`).

### GPU and platform switches

`main.cjs:10-14` forces ANGLE's Metal backend, `force_high_performance_gpu`, and `ignore-gpu-blocklist` — consistent
with the Apple-GPU workarounds in `renderer.js`. `main.cjs:12` comments that the OpenGL backend is deprecated.

### CSP and hardening

A tight CSP is set on HTML responses only (`main.cjs:16-25`, `main.cjs:150-152`): `default-src 'self'`, with
`'unsafe-inline'` allowed for script/style only because `index.html`'s import map and fade-in snippet are inline.
Notably `connect-src 'self'` — which means **the desktop build cannot reach the relay**. Online play is web-only in
practice; this is a real functional divergence between the two deployments and is not documented as a limitation.

`contextIsolation: true, sandbox: true` (`main.cjs:57`), and outbound links are pushed to the system browser via
`setWindowOpenHandler` (`main.cjs:61`). The preload surface is 9 lines and exposes only `platform`, `isFullScreen`,
`setFullScreen`, `onFullScreenChange` (`electron/preload.cjs:4-9`) — the game only ever reaches native code for
fullscreen, so the attack surface is minimal.

### Desktop-specific engineering

Two things stand out as genuinely careful:

1. **Fullscreen state reconciliation.** `main.cjs:63-74` handles the macOS quirk that "ignores requests made
   mid-transition": it remembers the *wanted* state, marks transitions it started with `ours`, and re-applies on
   `enter-/leave-full-screen` if the settled state disagrees. Shortcuts (F11, ⌘⌃F, ⌘↩, and ⌘Q from anywhere) are
   caught in `before-input-event` so the page's key handling and pointer lock cannot swallow them (`main.cjs:77-86`).
2. **Byte-range media serving.** `<audio>` seeking needs 206 responses, so `rangeResponse` (`main.cjs:103-117`)
   implements a proper RFC-7233 subset with `Content-Range`/`Accept-Ranges` and a 416 path. This ties to packaging:
   `package.json:11` uses `--asar.unpackDir=songs` and `main.cjs:143` rewrites the path from `app.asar/songs` to
   `app.asar.unpacked/songs` — songs ship *outside* the archive specifically so media can seek in them.

Also present: window-state persistence in `userData` with an `onScreen()` bounds check against all displays
(`main.cjs:42-44`, `main.cjs:48`), and a `powerSaveBlocker` started on focus / released on blur to stop App Nap
throttling the game loop (`main.cjs:95-98`).

`package.json:11` packages darwin arm64+x64 only, with `--ignore` excluding `dist|build|node_modules|docs|tools|server`.
The `prepackage` script runs `npm run check` (a `node --check` syntax pass over src/electron/build/tools/server/src,
`package.json:10`) and `npm run music`.

### Web deployment

`tools/build-dist.py` (1.3 KB) and `tools/release-pages.sh` (0.9 KB) produce a static Cloudflare Pages build, which is
why the relay's origin allow-list targets `*.inkwave-aah.pages.dev` (`server/src/index.js:22`). `package.json:23`
deploys the relay separately via `wrangler`. So the two halves of the web product ship independently: static assets to
Pages, relay to Workers.

## 9. Code quality observations

### Notable engineering decisions

**The GPU/CPU twin-edge contract is the single best idea in the world layer.** Duplicating `blobWobble` in JS
(`paint.js:43`) and GLSL (`paint.js:74`) is a real duplication smell in the abstract, but it is the *mechanism* that
makes a coarse 25 cm gameplay grid agree with a fine rendered edge. The design is explicit about the boundary: cosmetic
detail never claims turf (`paint.js:6-8`).

**Idempotent splat redraw via split blend equations.** Using `MaxEquation` for alpha while RGB is source-over
(`paint.js:380-382`) lets the growth animation re-emit the same geometry every frame with no accumulation. This is a
much simpler design than ping-ponging atlas targets.

**Deterministic seeded replication rather than streamed ink.** Sending `(centre, radius, team, seed, kind, stretch)`
and re-running the identical `blobWobble` on every client (`netmatch.js:109-114`) means ink costs ~13 numbers per
splat instead of a texture delta, and every screen is guaranteed identical.

**Asymmetric clock correction.** `delay` is fast to grow and slow to shrink (`netmatch.js:274`); the playback rate
slows rather than extrapolating when the buffer is thin (`netmatch.js:281`); corrections use a critically damped spring
rather than a snap (`netmatch.js:340-342`). This is textbook-quality netcode interpolation.

**Hibernation-aware Durable Object.** Rebuilding membership from socket attachments (`index.js:53-55`) plus
runtime-answered pings (`index.js:52`) means an idle room costs no DO wakeups.

**Defensive chunk patching.** `patchShadowFilter` verifies its regex matched before replacing (`renderer.js:69`) —
the right way to monkey-patch a vendored library's GLSL.

**Hash-gated asset application.** Lightmap bakes are checksummed against the layout and explicitly rejected as stale
(`main.js:272`), and the texture URL carries `?h=<hash>`. `build/check-maps.mjs` runs the same layout validation in CI
(overlaps, ramp steepness, bounds, spawn pads — requiring buried pieces to differ in top height by ≥8 cm, the same
6 cm threshold the paint grid marks dead cells with).

**Compile-time discipline in texlib.** Rolled loops via `uOne`, no integer modulo, pre-declared noise requests, async
compile, and a material-group split so no single uber-program gets huge (`texlib.js:34-36`). This is a genuinely
unusual level of awareness about driver behaviour.

### Complexity hotspots

- `src/world/props.js` — 3240 lines, ~62 prop types, a 2048² Canvas2D atlas, a merge/bucket system and two cloth
  shaders in one file. Should be at least four modules.
- `src/world/props-marina-vessels.js` (2244) and `props-marina-dock.js` (1855) are more of the same, loaded
  unconditionally even though only Halyard uses them.
- `src/world/environment.js` — 3003 lines of shaders, JS geometry builders and theme data; the `THEMES` table alone is
  70 lines of interleaved art direction.
- `Level.buildGeometry` (`level.js:248-385`) — ~135 lines with five nested loops emitting bevel strips and octant
  corner patches. Correct-looking but very hard to modify.
- `PAINT_FS` (`paint.js:67-214`) — ~150 lines of GLSL with four nested loops, five `smin` chains and a drip subsystem;
  a shader change here needs the JS twin updated too.
- `src/world/stages/crossmarket/` is the outlier: 11 files, 3276 lines, splitting into `street.js`, `tram.js`,
  `buildings.js`, `hall.js`, `kit.js`, `landing.js`, `scenery.js`, `props.js` — while the other six stages use the
  uniform 4-file layout. Either the other stages are under-decomposed or crossmarket is over-decomposed.

### Duplication across the 8 stage prop files

This is the most significant smell found. Measured verbatim (whitespace-normalised, lines >12 chars):

| pair | % of file A's lines present in B |
|---|---|
| **cargo → kelpline** | **92.8 %** |
| kelpline → tidewater | 11.3 % |
| saltpan → tidewater | 12.1 % |
| kelpline → saltpan | 12.3 % |
| cargo → saltpan | 12.3 % |
| lockgate → saltpan | 11.4 % |
| (all other pairs) | 8–12 % |

`cargo/props.js` (1845 lines) and `kelpline/props.js` (1844 lines) differ by only **211 `Compare-Object` entries**, and
essentially all of them are renames: `D.cargo_crane` vs `D.kelpline_*`, `'CARGO'`/`'CARGO TERMINAL'` lettering, and
the "Cargo Terminal (ported from PR #8, 'Kelpline Terminal' rebuild)" header (`cargo/props.js:1`). The
destructuring lines are byte-identical (`cargo/props.js:16` = `kelpline/props.js:16`). **~1700 lines of near-verbatim
copy-paste shipped as a second stage.** A shared `props-terminal.js` parameterised by palette and signage strings
would remove it.

The 8–12 % baseline across all other pairs is expected: shared conventions documented in each header (metres, Y up,
`pos` = base point, `rotY` turns local +Z, runs extend along local +X), the same `NS = (m) => H.noShadow ? ... ` alias
line, and identical destructuring boilerplate. That floor is a sign the conventions are well-established but were never
factored into a shared base.

`murals.js` duplication is low (2.5–14.5 % vs. tidewater), which is the right outcome — decals are genuinely
stage-specific.

Another duplication: `mirrorDef` exists in `level.js:408-415`, and a **second, near-identical `mirror` function** is
hand-written in `build/check-maps.mjs:15-17` for the validator. If the mirroring rule ever changes, the checker would
silently validate the wrong geometry.

Similarly, the zone-flood radius/easing function is duplicated as a comment-acknowledged copy: `zoneMarks.js:16` says
the capture-flood crest uses "the same radius function as `PaintSystem.flood`" — i.e. two implementations kept in sync
by hand.

### Dead code and reserved surface

Small but real:

- `_ownership(d)` / `_ownership() {}` — an empty stub wired to a live message type `'own'`
  (`netmatch.js:219`, `netmatch.js:709`). The wire format advertises a capability that does not exist.
- `NetMatch.go()` is an empty no-op with a comment explaining it is a hook that moved elsewhere
  (`netmatch.js:97`).
- `_voices(dt)` takes a `dt` parameter and never uses it (`netmatch.js:432`).
- `src/world/levelMaterial.js:62` declares `uPpm` with a comment "(from the paint system, set per draw)" but the
  constructor default is a hardcoded `20`, and `PaintSystem.ppm` varies per stage (18–30) — a latent mismatch worth
  verifying.
- `mock.js` (346 lines) exists for offline netplay and is not part of online play.

### Smaller observations

- The `_building` flag (`main.js:217`) correctly gates simulation during a stage rebuild, with a comment noting the
  reason (`main.js:215-216`): the rebuild awaits a lightmap fetch *between* swapping `G.level` and `G.paint`, so a
  frame in between would raycast the new level and sample the old paint atlas. Good awareness of an async hazard.
- `frozen` / `_building` share one early-return at `main.js:1056`.
- `paint.js:877` guards against "a face id from a stage being swapped in under a still-running match" in `sample()` —
  a defensive check for a race the `_building` gate is meant to prevent. Belt and braces.
- `MAX_QUADS = 6000` (`paint.js:31`) is a hard cap; exceeding it triggers a mid-frame `_drawQuads()` flush
  (`paint.js:654`), which is correct but means worst-case frame cost is unbounded in draw calls.
- The GTAO/`scene.overrideMaterial` interaction is handled explicitly — `zoneMarks.js:23` hides the zone-mark mesh from
  the GTAO normal pass.
- `src/core/` is only 3 files and 376 lines total; `input.js` is 134 lines. The core layer is appropriately thin, but
  `renderer.js` carries Apple-specific, chunk-patching hardware workarounds that arguably belong in a
  `renderer-patches.js`.
- `styles/` is 424 KB of CSS across two files (`ui.css` at 2671 lines / 291 KB), with no preprocessing — consistent
  with the no-build-step constraint but a large surface for one file.
